### 📝 코드/컬럼 수정 상세 (Detailed Edits)

- **독립 레코드(Independent Record) 원칙 (INV-01-2)**:
  - 식재료 등록 시 기존 레코드가 존재하더라도 수량을 합산(UPDATE)하지 않고 무조건 신규 PK(`ingredient_id`)를 생성하여 개별 `INSERT`하도록 보장.
  - 소비기한 미입력 시 마스터 식재료의 `default_shelf_days`를 당일 날짜에 자동 가산하여 기본값 설정.
- **방어적 소비 차감 로직 (`Math.max`)**:
  - 잔여 수량 연산 시 `Math.max(0, current - consume)`를 적용하여 음수 수량을 방지하고, 0 이하가 될 경우 `status = 'CONSUMED'`로 자동 상태 전이.
  - 소비 수량 미입력 시 전량 소비로 간주.
- **KST 기준 실시간 D-Day 연산**:
  - Supabase DB 타임존이 UTC인 환경에서 자정(00시~09시) 사이 날짜 차이로 인한 D-Day 왜곡을 방지하기 위해 `(ui.expire_date - (CURRENT_TIMESTAMP AT TIME ZONE 'Asia/Seoul')::date) AS d_day` 적용.
- **소유권 검증 (Ownership Isolation)**:
  - 수정/삭제/소비 API 호출 시 `user_id` 조건을 필수로 바인딩하여 타인의 식재료 접근 시 `INV_WARN_NOT_FOUND` (404 Not Found)로 차단.

- **선입선출(FIFO) 및 혼합차감 금지 원칙 (INV-04-2, REC-03-1)**:
  - 요리 완료(`POST /api/v1/matching/cook/{recipeId}`) 시 `expire_date ASC, created_at ASC` 순으로 소비기한 임박 재료부터 차감.
  - 원재료 보유량이 필요량보다 부족한 경우, 대체재료와 섞어서 차감하지 않고 원재료 전량 차감(Partial Deduction) 후 종료.
  - 양념/소스 카테고리(`is_sauce = TRUE`)는 차감 연산 대상에서 원천 배제.
- **스마트 매칭 점수 산출 공식 및 Hard Gate (MATCH-01-1)**:
  - 주재료 보유 개수가 0개인 레시피는 점수 계산 없이 매칭률 0%로 처리되어 추천 목록에서 완전 배제.

  - Bonus Score: D-Day $0 \le \text{D-Day} \le 3$ 임박 주재료 +10점, 임박 부재료 +5점 (최대 20점 상한, 이미 경과된 유통기한 D-Day < 0은 가산점 배제).
- **익명 레시피(Anonymous Recipe) 데이터 보존 및 권한 격리 (USER-02, SYS-01)**:
  - 회원 탈퇴 시 레시피 작성자 ID를 `NULL`로 처리하여 익명 보존.
  - 작성자 ID가 `NULL`인 레시피에 대한 수정/삭제 요청 시 `403 Forbidden` (`RECIPE_WARN_NOT_AUTHOR`)으로 안전하게 차단.
- **PostgreSQL JDBC TIMESTAMPTZ 변환 호환성**:
  - `Recipe` 엔티티의 `createdAt`, `updatedAt` 필드를 `java.time.OffsetDateTime`으로 정의하여 드라이버 타입 변환 예외 원천 해결.
- **물리 DB 테이블 스펙 준수**:
