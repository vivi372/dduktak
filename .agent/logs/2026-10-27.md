## 💬 Command 03. 레시피 등록 POST /api/v1/recipes 400 Bad Request 원인 분석 및 해결

### 1. 작업 목적 및 상세 내역
- **문제 진단 (백엔드 로그 분석)**:
  - 사용자의 레시피 신규 등록 요청(`POST /api/v1/recipes`) 시 400 Bad Request 발생.
  - 백엔드 Spring Boot 로그 분석 결과:
    ```sql
    SELECT master_ingredient_id, category_id, name, default_unit, default_shelf_days, created_at 
    FROM public.ingredient_master WHERE master_ingredient_id = ?
    Parameters: 61(Long) -> Total: 0
    ```
    이후 트랜잭션 롤백과 함께 예외 발생:
    ```text
    ERROR [4D0484] RecipeService.createRecipe() - Exception: CustomException - 요청 입력값이 올바르지 않습니다.
    WARN [4D0484] GlobalExceptionHandler : [CustomException] Code: COMMON_FIELD_INVALID_INPUT, Message: 요청 입력값이 올바르지 않습니다.
    ```
- **근본 원인**:
  1. `RecipeService.java`의 `validateRecipePayload`: 등록할 각 식재료의 `masterIngredientId`가 `ingredient_master` 테이블에 실존하는지 검증(`findById`).
  2. 실제 Supabase PostgreSQL `ingredient_master` 테이블은 시드 데이터 적재 시 시퀀스 생성 결과 ID가 1~103번 범위(총 74종)로 부여되어 있으며, **ID 61은 DB에 존재하지 않음** (식용유의 실제 DB ID는 `28`).
  3. 프론트엔드의 `useMasterIngredients` 훅에 `initialData: mockMasterIngredients`, `staleTime: 30분`이 설정되어 있어 실제 백엔드 DB의 최신 마스터 데이터를 조회하지 않고 정적 목 데이터를 사용함.
  4. 기존 `mockMasterIngredients`는 1번부터 74번까지 임의의 연속 번호로 작성되어 있어(식용유 = 61), 사용자가 콤보박스에서 식용유를 골라 등록 요청 시 백엔드로 `masterIngredientId: 61`이 전송되어 검증 실패.
  5. 또한 백엔드 `SecurityConfig.java`에서 `GET /api/v1/inventory/master-ingredients` 및 `GET /api/v1/recipes/categories` 등 메타데이터/참조용 GET 엔드포인트가 `authenticated()`로 묶여 있어 비인증 또는 토큰 로딩 중 호출 실패 시 mock으로 강제 폴백되는 취약점이 있었음.

- **개선 조치 내역**:
  1. **백엔드 `SecurityConfig.java`**:
     - `GET /api/v1/inventory/master-ingredients`, `GET /api/v1/recipes/categories`, `GET /api/v1/recipes/**`에 대해 `permitAll()` 비인증 공개 허용 설정.
  2. **프론트엔드 `master_ingredients.mock.ts`**:
     - PostgreSQL `ingredient_master` 테이블의 실제 74종 식재료 시퀀스 ID(식용유: 28, 계란: 9, 대파: 2, 멸치: 64 등)와 100% 동기화.
     - `mockCategories` 6대 카테고리 정의 유지.
  3. **프론트엔드 `useInventory.ts` (`useMasterIngredients`)**:
     - `initialData` 대신 `placeholderData: mockMasterIngredients`를 적용하여, 초기 화면 렌더링 즉시성을 유지하면서도 마운트 시 백엔드 DB의 실제 마스터 식재료 데이터를 백그라운드에서 fetch하여 동기화하도록 개선.
  4. **프론트엔드 `RecipeFormPage.tsx`**:
     - 기본 선택 식재료인 '계란'의 `masterIngredientId`를 실제 DB ID인 `9`로 정정 (`18` 또는 `2` -> `9`).
