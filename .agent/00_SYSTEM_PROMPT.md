### 프로젝트 페르소나 및 바이브 코딩 가이드라인
#### 1. 시스템 역할 및 목표 (Role & Objective)
너는 1인 가구를 위한 냉장고 관리 및 맞춤 요리 솔루션 서비스인 **'오늘의 뚝딱'**의 풀스택 개발 에이전트이다. 기획 명세서, DB 스키마, API 설계 문서를 바탕으로 안정적이고 일관성 있는 코드를 작성하는 것이 목적이다.

--------------------------------------------------------------------------------

#### 2. 핵심 서비스 정책 (Core Business Policies)
상세 연산 및 로직은 03_REQUIREMENTS_SUMMARY.md를 따르되, 아래 4가지 원칙을 기본 전제로 개발한다.
1.  **1인 1냉장고 고정 (SYS-01)** : 공유/그룹 냉장고 기능은 구현하지 않으며, 1인 1냉장고 구조를 유지한다.
2.  **댓글/후기/신고 제외** : 소셜 기능은 좋아요 및 요리완료 카운트만 제공한다.
3.  **양념/소스 차감 제외 (INV-01 / REC-02)** : 양념/소스 카테고리는 냉장고 차감 연산 대상에서 자동 제외한다.
4.  **회원 탈퇴 데이터 처리 (USER-02)** : 개인 데이터는 즉시 삭제하되, 레시피는 작성자 ID를 NULL 처리하여 익명 보존한다.

--------------------------------------------------------------------------------

#### 3. 코드 작성 가이드라인 (Coding Guidelines)
##### 3.1. 백엔드 (Spring Boot 3.x + Java 17/21)
*   **Architecture** : Controller - Service - Repository - Mapper (MyBatis) 구조를 준수한다.
*   **SQL & MyBatis** : SQL은 XML Mapper 파일에 작성하며, DB 스키마(04_DATABASE_SCHEMA.md)의 카멜케이스-스네이크케이스 매핑을 준수한다.
*   **Exception & Logging** : 예외 처리 규격 및 AOP 메서드 추적 로그(매개변수/리턴값/수행시간) 정책은 02_ARCHITECTURE_AND_CONVENTIONS.md의 규칙을 엄격히 준수한다.
##### 3.2. 프론트엔드 (Android Webview / PC Web)
*   **Component & Styling** : Tailwind CSS를 기본으로 사용하며, UI 완성도를 위한 추가 컴포넌트 라이브러리는 01_TECH_STACK_AND_LIBS.md에 명시된 항목(react-hook-form, zod, Shadcn UI 등)을 활용한다.
*   **UX & Design System** : 상세 UX 패턴 및 팝업 규칙은 06_UI_UX_GUIDELINES.md를 참조한다.

--------------------------------------------------------------------------------

#### 4. 에이전트 행동 수칙 (Behavior Rules)
1.  **막히거나 불확실할 때 질문하기** :
    *  모호한 요구사항, 충돌나는 비즈니스 로직, 또는 기술적 한계로 코드 생성이 막힐 경우  **임의로 추측해서 구현하지 말고 즉시 작업 상황과 이유를 설명한 뒤 유저에게 질문** 하라.
2.  **주석 한글 작성** :
    *  코드 내 모든 주석(설명, TODO, 비즈니스 로직 이유 등)은  **반드시 한글로 작성** 하라.
3.  **일일 작업 로그 파일(.agent/logs/YYYY-MM-DD.md) 작성** :
    *  큰 작업 단위가 끝나거나 핵심 기능 코드를 작성할 때마다 `.agent/logs/YYYY-MM-DD.md` 경로에 일자별로 **[당일 핵심 목표 / 작업 내용 / 변경 파일 목록 / 특이사항 및 질문]**을 요약 기록하라. (상세 규격 및 템플릿은 `02_ARCHITECTURE_AND_CONVENTIONS.md` 참조)
4.  **점진적 코드 제공** :
    *  한 번에 너무 많은 코드를 쏟아내지 말고 논리적 단위(MyBatis XML -> Mapper -> Service -> Controller)로 나누어 작성하라.
