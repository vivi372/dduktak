### 📄 [모듈 2 상세 명세서] 내 재료 관리소 (Inventory)
#### 1. 개요 및 시스템 정책
*   **목적** : 표준 식재료 마스터 기반으로 내 재료의 생명주기(등록 $\rightarrow$ 그룹화 조회/수정 $\rightarrow$ 소비/삭제 $\rightarrow$ 만료)를 효율적으로 관리하고, 레시피 매칭 및 FIFO 차감 데이터를 제공.
*   **UX 핵심 컨셉** : 표준 식재료 단위로 메인 카드를 그룹화하여 화면 복잡도를 최소화하고, 클릭 시 아코디언을 펼쳐 소비기한·메모가 다른 개별 레코드를 다루는  **2-Tier Accordion UX**  채택.
*   **데이터 보존 정책** :
*  동일 재료라도 유저 메모 및 소비기한 보존을 위해 별도 레코드로 각각 저장.
*  소비기한 만료 재료는 자동 삭제하지 않고 별도의 '소비기한 만료 영역'으로 이동시켜 데이터 오삭제 방지.

#### 2. 세부 기능 요구사항 (Functional Requirements)
##### 2.1. 식재료 등록 (Create)
*   **INV-01-1 [Searchable Select 기반 등록 폼]** :
*  표준 식재료 (필수): Searchable Select(Combobox)로 ingredient_master 테이블 조회 후 선택. (자유 텍스트 입력 불가)
*  보관장소 (필수): 라디오 버튼 또는 Select (REFRIGERATED: 냉장, FROZEN: 냉동, ROOM_TEMP: 실온). 선택 시 마스터 기본값 자동 세팅.
*  소비기한 (필수): DatePicker. 마스터 재료의 권장일(오늘 + N일)로 초기 세팅되며 유저가 자유 변경 가능.
*  수량 (필수): 양의 정수 (기본값: 1, 숫자 패드 inputmode="numeric" 적용).
*  수량 단위 (선택): 드롭다운/입력 (개, g, ml, 팩, 포기 등, 기본값: 개).
*  표시용 메모/별칭 (선택): 최대 30자 (예: "편의점 1+1", "엄마가 준 김치").
*   **INV-01-2 [독립 레코드 저장 정책]** :
*  동일한 마스터 재료, 동일한 날짜라도 수량을 무조건 합산(UPDATE)하지 않고  **각각 독립된 레코드(PK)로 저장** 하여 유저의 메모와 구매 인스턴스를 완전 보존.
*   **INV-01-3 [외부 스캔/OCR 등록 및 스캔 실패 예외 처리 흐름]** :
*   **바코드 스캔** : 스캔 $\rightarrow$ 공공 API 조회 $\rightarrow$ 마스터 재료 자동 세팅 $\rightarrow$ 유저가 소비기한/수량 확인 후 등록.
*   **영수증 OCR** : 영수증 사진 업로드 $\rightarrow$ OCR 파싱 $\rightarrow$ 마스터 일치 품목 '임시 목록' 팝업 제공 $\rightarrow$ 유저 확인 후 일괄 등록.
*   **스캔 실패 예외 처리** : 바코드 인식 실패 또는 영수증 미등록 상품인 경우, 안내 팝업을 노출하고 [다시 촬영하기]와 [수동 재료 등록하기]의 2가지 선택권을 제공하여 유저 흐름 단절 방지.
*   **부재 식재료 처리** : 마스터에 없는 재료는 커뮤니티의 '요청 게시판'을 이용하도록 안내하여 등록 UI를 시종일관 깔끔하게 유지.

##### 2.2. 식재료 조회 및 필터링 (Read) - 2-Tier Accordion UX
*   **INV-02-1 [1차 뷰: 마스터 재료별 그룹화 카드 (Representative Card)]** :
*  동일한 ingredient_master_id를 가지며 status = 'ACTIVE'인 레코드들을 하나로 그룹화하여 카드 1개로 표기.
*   **표시 항목** : 표준 재료명, 보관장소, 총 수량 합계(예: 총 3개),  **가장 임박한 D-Day 배지** .
*   **기본 정렬** : 보유한 여러 인스턴스 중  **가장 임박한 D-Day가 급한 순** 으로 카드 상단 노출.
*   **기본 접힘(Collapsed) 정책** : 대표 카드 배지에서 이미 가장 임박한 D-Day를 시각적으로 표기하므로, 리스트 가독성과 빠른 스크롤을 위해  **모든 대표 카드는 기본적으로 접힌 상태** 로 노출.
*   **INV-02-2 [2차 뷰: 아코디언 펼침 상세 목록 (Detailed Instances)]** :
*  대표 카드를 클릭/터치하면 하단으로 아코디언 영역이 확장됨 (44px 이상 터치 타겟 확보).
*   **표시 항목** : 개별 소비기한, 개별 수량, 유저 메모/별칭, 개별 관리 버튼([소비], [수정], [삭제]).
*   **정렬** : 아코디언 내부에서도 소비기한 임박순 정렬.
*   **INV-02-3 [검색 및 드롭다운 필터]** :
*   **텍스트 검색** : 표준 재료명 및 표시용 메모/별칭 대상 키워드 검색 (실시간 반응).
*   **보관장소 Select 필터** : 전체, 냉장, 냉동, 실온.
*   **카테고리 Select 필터** : 전체, 채소류, 육류, 유제품 등.
*   **INV-02-4 [소비기한 만료 영역 (Expired List)]** :
*  소비기한이 도과한 재료(D-Day < 0)는 메인 카드 목록에서 제외하고, 화면 하단  *"소비기한이 지난 재료 N개 [보기]"*  아코디언 영역으로 이동.
*  만료 영역 내 개별 아이템에 대해 [버리기(폐기)], [먹음(소비)], [소비기한 연장(수정)] 버튼 제공.

##### 2.3. 식재료 수정 (Update)
*   **INV-03-1 [개별 인스턴스 직접 수정]** :
*  아코디언을 펼쳐 특정 개별 레코드의 수량, 수량 단위, 소비기한, 보관장소, 메모 수정 가능.
*  표준 식재료 자체는 변경 불가 (변경 필요 시 삭제 후 재등록).
*  수량을 0 이하로 수정 시 "0개는 입력할 수 없습니다. 삭제하시겠습니까?" 얼럿 유도.

--------------------------------------------------------------------------------

##### 2.4. 식재료 삭제 및 소비 처리 (Delete & Consume)
*   **INV-04-1 [유저 수동 삭제 및 소비]** :
*   **삭제** : 등록 실수 등의 사유로 [삭제] 클릭 시 DB에서 해당 레코드 완전히 삭제/소프트 삭제 (status = 'DELETED').
*   **수동 소비** : 아코디언 내 특정 레코드의 [소비 완료] 클릭 시:
*  수량이 2개 이상일 경우:  **"1개 차감"**  vs  **"전체 소비"**  선택 팝업.
*  수량이 0이 되면 냉장고 목록에서 제거 (status = 'CONSUMED').
*   **INV-04-2 [요리 완료 시 자동 선입선출(FIFO) 차감]** :
*  레시피 상세 화면에서 [이 레시피로 요리하기] 클릭 시 백엔드 트랜잭션 수행:
1. 레시피 필요 표준 재료 ID 및 수량 파악.
2. 유저의 냉장고에서 해당 표준 재료 ID의 status = 'ACTIVE' 레코드들을 expiration_date ASC (소비기한 임박순)으로 조회.
3. 가장 급한 레코드부터 차례대로 수량을 차감.
4. 레코드 수량이 0이 되면 CONSUMED 상태로 전환 후 남은 차감 수량을 다음 임박 레코드에서 연속 차감.
