# 🧪 [오늘의 뚝딱] 핵심 비즈니스 인수 테스트 시나리오 (Acceptance Criteria)

## 📌 문서 목적
본 문서는 백엔드/프론트엔드 구현 완료 후 기능의 정상 작동 여부를 스스로 검증하거나 통합 테스트 코드를 작성할 때 기준이 되는 핵심 비즈니스 인수 테스트(Acceptance Criteria)를 정의한다.

### [시나리오 01] 선입선출(FIFO) 재료 차감 및 양념류 예외 검증 (Inventory & Recipe)
* **목적**: 요리 완료 시 소비기한이 가장 급한 재료부터 순차 차감되고, 양념류는 보존되는지 검증한다.
* **Given (사전 조건)**:
  * `대파 (인스턴스 A)`: D-1, 수량 1뿌리
  * `대파 (인스턴스 B)`: D-5, 수량 2뿌리
  * `진간장`: 카테고리 `양념/소스/조미료`, 수량 100ml
  * 필요 재료: `대파 2뿌리`, `진간장 15ml`
* **When (실행)**: 유저가 [이 레시피로 요리하기] 팝업에서 [확인 및 냉장고 차감]을 클릭한다.
* **Then (결과 검증)**:
  1. `대파 (인스턴스 A)` 수량 0, 상태 `CONSUMED` 변경 및 목록 삭제.
  2. `대파 (인스턴스 B)` 수량 2 -> 1로 차감 (`UPDATE`), `ACTIVE` 유지.
  3. `진간장` 수량 변동 없이 100ml 유지.
  4. 해당 레시피 `cooked_count` +1 증가.

### [시나리오 02] 냉장고 털기(냉털) 스마트 매칭 엔진 검증 (Recipe Engine)
* **목적**: 주재료 미보유 레시피는 필터링되고, 소비기한 임박 재료가 포함된 레시피가 최상단에 추천되는지 검증한다.
* **Given (사전 조건)**:
  * 냉장고: `양파 D-1` (임박), `계란 D-10` (여유), `돼지고기` 미보유.
* **When (실행)**: [🟢 내 냉장고 뚝딱 매칭] 토글 활성화.
* **Then (결과 검증)**:
  1. `제육볶음`(주재료 돼지고기 미보유) 매칭 목록에서 제외.
  2. `양파계란볶음`(주재료 양파 D-1) 가산점 받아 추천 최상단 위치.

### [시나리오 03] 스캔/OCR 실패 시 예외 복구 흐름 검증 (Inventory UX)
* **Given (사전 조건)**: 바코드 스캐너 또는 영수증 촬영 화면.
* **When (실행)**: 바코드 인식 실패 또는 OCR 파싱 실패.
* **Then (결과 검증)**:
  1. 안내 팝업(AlertDialog) 노출.
  2. [다시 촬영하기]와 [수동 재료 등록하기] 버튼 제공.
  3. [수동 재료 등록하기] 클릭 시 `/inventory/new` 이동.

### [시나리오 04] 회원 탈퇴 시 레시피 데이터 익명화 보존 검증 (Data Integrity)
* **Given (사전 조건)**: `user_id = 100` 회원이 작성한 `recipe_id = 1`.
* **When (실행)**: `user_id = 100` 탈퇴 요청 및 삭제.
* **Then (결과 검증)**:
  1. `recipe_id = 1` 레코드 유지.
  2. `user_id` 컬럼 값 `NULL` 변경 (`ON DELETE SET NULL`).
  3. 작성자 닉네임 "(알 수 없음)" 또는 "탈퇴한 사용자"로 노출.

### [시나리오 05] 소비기한 만료 영역 자동 분리 및 2-Tier 아코디언 검증 (Inventory UI)
* **Given (사전 조건)**: `두부 A (D+1 만료)`, `양파 A (D-2 임박)`, `양파 B (D-10 안심)`.
* **When (실행)**: 내 재료 관리소(`/inventory`) 진입.
* **Then (결과 검증)**:
  1. 만료된 `두부 A` 최하단 "소비기한이 지난 재료 1개 [보기]" 영역으로 이동.
  2. `양파` 대표 카드는 수량 "2개", 배지 "D-2", 기본 상태 Collapsed.
  3. 대표 카드 클릭 시 아코디언 펼쳐지며 인스턴스 A, B 세부 카드 노출.
